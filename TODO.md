- Перед каждой сборкой активировать установленный ESP-IDF:

- Использовался ESP-IDF `v6.1-dev-4811-gfce70533fa`, target `esp32`.

- PS/2-мышь: CLK — GPIO 26, DATA — GPIO 25.
- На имеющейся плате уже включено Flash Encryption в DEVELOPMENT mode. Пользователю шифрование как функция проекта не важно: оно включено в локальной сборке для совместимости с этой платой. Не делать обязательное шифрование для всех плат целью исправлений.

- Эта локальная конфигурация успешно собрана: приложение `0x11F260`, в разделе осталось 23%. Аппаратный запуск после последнего добавления `nvs_keys` в переписке не подтверждён.
- `sdkconfig` и `sdkconfig.old` игнорируются Git. К началу ревью в рабочем дереве были изменения `sdkconfig.defaults` и неотслеживаемая `.cache/`; их не удалять и не откатывать как часть ревью.
- В логе плата определяет flash 4 МБ при заголовке образа 2 МБ. Это предупреждение не было причиной падения NVS.

## P1 — исправить в первую очередь

- [ ] **1. Чистая сборка не проходит из-за конфигурации таблицы разделов.**
  - Место: `sdkconfig.defaults:5`.
  - Выбранная `PARTITION_TABLE_SINGLE_APP_LARGE_ENC_NVS` зависит от настроек NVS/Flash Encryption, которые отсутствуют в defaults. Без локального `sdkconfig` ESP-IDF выбирает `PARTITION_TABLE_SINGLE_APP` и раздел приложения 1 МБ.
  - Подтверждено чистой сборкой копии: образ `0x10D7B0` не помещается в `0x100000`, переполнение `0xD7B0`.
  - Это упущение предыдущей правки defaults. Сделать воспроизводимую конфигурацию с достаточно большим разделом приложения, сохранив возможность работы как с обычными, так и с уже зашифрованной платой.

- [ ] **2. Выход за границы массива при запросе текущего набора скан-кодов.**
  - Место: `main/esp32-ps2dev.cpp:1091–1093`.
  - Ответ на `F0 00` использует `resp[_scan_code_set]` для массива из трёх элементов. При Set 3 индекс равен 3; при Set 2 выбирается не соответствующий ему элемент.
  - Выход за границы для индекса 3 воспроизведён отдельной проверкой с AddressSanitizer/UndefinedBehaviorSanitizer.
  - Исправить формирование ответа и проверить запрос после выбора каждого поддерживаемого набора (2 и 3). Одного изменения индекса недостаточно: на самой PS/2-шине ответ должен быть номером набора (`0x02`/`0x03`); `0x43`, `0x41`, `0x3F` — значения после трансляции контроллером хоста. Linux `atkbd_select_set()` на нетранслирующем порту проверяет ответ `0x03` после выбора Set 3.

- [ ] **3. Ранняя команда управления LED может вызвать падение.**
  - Места: `main/main.cpp:275–295`, `main/bt_keyboard.cpp:357`, `main/bt_keyboard.cpp:1733`.
  - PS/2 уже принимает команды, а LED callback регистрируется до создания `led_device_map_semaphore` внутри `BTKeyboard::setup()`. В этом промежутке команда LED от BIOS приводит к `xSemaphoreTake(nullptr, ...)`.
  - Проверять готовность Bluetooth или сохранять LED-состояние и передавать его после завершения инициализации.

- [ ] **4. HID-отчёты читаются без проверки границ.**
  - Места: `main/bt_keyboard.cpp:1194–1197`, `1211–1242`, `1285–1296`.
  - Bitmap мультимедийных клавиш обращается к `array_usages[bit_count]` без проверки размера; `operator[]` создаёт пустое описание неизвестного отчёта. Array-ветка не проверяет достаточность входных байтов и ненулевой `report_count`. Обработчику мыши вообще не передаётся длина буфера.
  - Неизвестный, укороченный отчёт или неудачный разбор дескриптора могут привести к чтению за границами памяти; деление на нулевой `report_count` также не исключено.
  - Перед обработкой проверять наличие описания, длину отчёта, диапазоны битов, размеры Usage-таблиц и делитель.

- [ ] **5. Байты PS/2 теряются при запрете передачи хостом.**
  - Места: `main/esp32-ps2dev.cpp:397–405`, `1640–1642`.
  - `write_wait_idle()` возвращает ошибку после таймаута, но вызывающий код игнорирует её и переходит к следующему байту пакета.
  - При удержании CLK низким хостом теряются байты, включая префиксы и коды отпускания; последовательность PS/2 повреждается.
  - Обрабатывать результат и сохранять неподтверждённую часть пакета для корректного продолжения передачи.

## P2 — функциональные ошибки

- [ ] **6. Отключение Bluetooth не отпускает удерживаемые клавиши.**
  - Места: `main/bt_keyboard.cpp:1263–1277`, `main/main.cpp:364–367`.
  - CLOSE меняет только `isConnected` и LED-таблицу. Состояния клавиш, модификаторов и кнопок мыши не сбрасываются; автоповтор старой клавиши продолжается.
  - Передавать событие отключения и отпускать состояния отключённого устройства.

- [ ] **7. Переполнение очередей незаметно теряет события.**
  - Места: `main/bt_keyboard.cpp:1300`, `1324`, `1342`; `main/esp32-ps2dev.cpp:500–502`, `1229`, `1245`, `898–899`.
  - Неблокирующие `xQueueSend()` могут завершиться отказом; результат не учитывается. Неудачное добавление PS/2-пакета также игнорируется. Потеря PS/2-кода отпускания вызывает залипание. Потерянный полный HID-отчёт может быть компенсирован следующим полным отчётом, но если нового отчёта нет, состояние остаётся устаревшим. Потеря относительного движения мыши необратима.
  - Определить политику перегрузки очередей и восстановления состояния, не блокируя Bluetooth callback на неопределённое время.

- [ ] **8. Пустой слот HID обрывает обработку остальных клавиш.**
  - Место: `main/main.cpp:73–74`.
  - Циклы `handle_key()` заканчиваются на первом нуле, хотя HID-массив не обязан быть уплотнённым и его порядок не определяет порядок нажатий.
  - Подтверждено проверкой: переход `[A, B, 0] → [0, B, 0]` ошибочно отпускает A и B вместо только A.
  - Проходить все допустимые слоты, пропуская нулевые значения. Обязательное условие: сначала обнулять весь `KeyInfo inf`/`KeyInfo_CCONTROL inf` в `push_key()`/`push_key_CCONTROL()`. Сейчас заполняются только `max` элементов и один нулевой терминатор; чтение всех десяти слотов без этого изменения захватит неинициализированный хвост.

- [ ] **9. Неверно читаются битовые поля мыши со смещением.**
  - Место: `main/bt_keyboard.cpp:1692–1704`.
  - В `getBits()` число читаемых байтов рассчитывается без учёта `StartBit % 8`; старшие биты полей, пересекающих границу байта, теряются. Для поля длиной 16 бит со смещением также недостаточен 16-битный промежуточный накопитель.
  - Подтверждено проверкой исходной функции: данные `{0x00, 0x01}`, `StartBit=1`, `NumBits=8` дают 0 вместо −128.
  - Исправить расчёт границ, ширину накопителя и проверку длины входного буфера.

- [ ] **10. Гонка при накоплении движения мыши.**
  - Места: `main/esp32-ps2dev.cpp:775–780`, `834–899`; задачи создаются на разных ядрах.
  - Одна задача изменяет счётчики, другая формирует отчёт и обнуляет их без общей синхронизации. Движение между чтением и сбросом теряется; команды хоста также меняют эти поля.
  - Сделать атомарное получение накопленного движения либо перенести владение состоянием в одну задачу.

- [ ] **11. Несколько клавиатур смешивают состояния.**
  - Места: `main/bt_keyboard.cpp:1203`, `1303–1324`; `main/main.cpp:314`, `345–364`.
  - Все устройства отправляют события в одну очередь без идентификатора источника, а предыдущий отчёт хранится в одном `infoBuf`. Отчёт второй клавиатуры может отпустить клавиши первой.
  - Хранить состояния по устройствам и объединять их перед формированием PS/2-событий.

- [ ] **12. Идентификатор HID-отчёта неполный.**
  - Места: `main/bt_keyboard.cpp:1195–1196`, `1208–1209`, `1633–1634`; `include/bt_keyboard.hpp:213–214`.
  - Ключ таблиц — `(device, report_id)`, без `map_index`. Разные карты одного устройства с одинаковыми Report ID перезаписывают параметры друг друга.
  - Учитывать индекс карты при разборе дескриптора и входного отчёта.

- [ ] **13. Однобайтовые мультимедийные коды получают случайные старшие биты.**
  - Место: `main/bt_keyboard.cpp:1232–1241`.
  - `key_temp` не инициализирован перед частичным `memcpy`. При копировании одного байта старший байт результирующего `uint16_t` остаётся неопределённым, и Usage-код не совпадает с таблицей.
  - Инициализировать временное значение для каждого элемента; корректно учитывать ширину и битовое расположение поля.

- [ ] **14. Диапазоны Usage не преобразуются в коды клавиш.**
  - Места: `main/bt_keyboard.cpp:1554–1557`, `1579–1582`, `1637`.
  - Для мультимедийного bitmap с `Usage Minimum/Maximum` парсер сохраняет границы, но не раскрывает диапазон в `temp_usages_array`: вместо кодов там оказываются нули. Такие кнопки не работают.
  - Формировать Usage-таблицу из диапазонов, учитывая constant/padding поля.

- [ ] **15. Режимы PS/2-мыши обрабатываются неправильно.**
  - Места: `main/esp32-ps2dev.cpp:698–704`, `1653–1655`.
  - `SET_STREAM_MODE` не устанавливает `_mode = STREAM_MODE`. Фоновая отправка проверяет только `_data_reporting_enabled` и продолжает работу даже после перехода в REMOTE_MODE.
  - Исправить переходы режима и в REMOTE_MODE отправлять движение по запросу хоста. Уточнение повторного ревью: в старой ветке WRAP_MODE в начале `reply_to_host()` уже было восстановление `_last_mode`; утверждение о его отсутствии было неверным. Фоновая отправка при этом не исключала WRAP_MODE. Проверить также порядок ответа `READ_DATA`: ACK отправляется напрямую, пакет движения ставится в общую очередь и может оказаться позади ранее накопленных пакетов.

- [ ] **16. Масштабирование мыши 2:1 применяется только к отрицательному движению.**
  - Место: `main/esp32-ps2dev.cpp:837–865`.
  - Вычисленное значение записывается обратно только в `if (!positive)`, положительный счётчик остаётся прежним.
  - Применять результат для обоих знаков и проверить значения 1–6 и выше.

- [ ] **17. Команда RESEND не повторяет предыдущие данные.**
  - Места: `main/esp32-ps2dev.cpp:569–574` для мыши, `1033–1038` для клавиатуры.
  - На RESEND отправляется ACK вместо повторной передачи предыдущих данных. Восстановление после ошибки PS/2 не работает.
  - Хранить необходимые переданные данные и реализовать ответ по протоколу соответствующего устройства.

- [ ] **18. Показ кода сопряжения блокирует Bluetooth callback на десятки секунд.**
  - Места: `main/bt_keyboard.cpp:604`, `763`; `main/main.cpp:147–184`.
  - GAP callback синхронно вызывает обработчик с длительным миганием LED и `vTaskDelay`, задерживая последующие GAP-события.
  - Отправлять код в отдельную задачу отображения и сразу возвращаться из callback.

- [ ] **19. Код сопряжения теряет ведущие нули.**
  - Места: `main/main.cpp:140–159`.
  - `NumDigits()` и обычный вывод числа показывают `003421` как `3421`; LED также отображает только четыре цифры. Passkey для Secure Simple Pairing/Security Manager должен отображаться шестизначным; это требование не относится к фиксированному legacy PIN `1234`.
  - Форматировать число шестью цифрами и обрабатывать все шесть позиций, включая ведущие нули.

## Упрощение структуры кода

Цель — сделать владение состоянием и путь события явными. Разбиение больших файлов полезно после выделения обязанностей; само по себе оно не исправляет общие static-поля и межзадачные гонки. Следующие предложения основаны на текущем коде, выигрыш по CPU/RAM не измерялся.

### 1. Отдельный HID-парсер и декодер — вместе с пунктами 4, 9, 12–14

- `bt_keyboard.cpp:1415–1730`: вынести разбор дескриптора, описание полей и чтение битов в независимый модуль без Bluetooth callbacks и FreeRTOS.
- Заменить static `s_parse_step`, `s_report_params`, `s_report_size`, `temp_usages_array` контекстом одного вызова парсера; результат сохранять по `(device, map_index, report_id)`.
- `parse_cmd()` сейчас делает `malloc/free` для каждого HID item. Достаточно локального `hid_report_cmd_t cmd{}` и выходного параметра по ссылке. Это убирает лишнюю работу с heap и ветви ошибки выделения памяти.
- Декодер получает буфер с длиной и готовое описание отчёта; возвращает нормализованное состояние клавиатуры/мыши или явную ошибку. Общий reader битов должен различать signed/unsigned поля.
- Проверки: усечённые дескрипторы и отчёты, невыравненные поля, Usage ranges, padding, одинаковые Report ID в разных картах.

### 2. Один владелец состояния ввода — вместе с пунктами 6, 8, 10, 11

- `main.cpp:314–415`, `417–470`: вынести преобразование отчётов в PS/2-события в модуль моста. `app_main()` оставляет настройку платы, запуск компонентов и задач.
- События содержат источник и тип (`Keyboard`, `Consumer`, `Mouse`, `Disconnected`). Bluetooth callback декодирует и передаёт событие; задача моста хранит состояния по устройствам, объединяет удерживаемые клавиши и управляет typematic.
- Удаление устройства пересчитывает суммарное состояние; отпускание клавиши одной клавиатурой не отпускает её, если другая всё ещё удерживает её.
- Таймер автоповтора хранит конкретную выбранную клавишу и срок следующего повтора. Позиция в HID-массиве не определяет порядок нажатий; порядок внутри одного отчёта принципиально неоднозначен.
- Для PS/2-мыши отдельно определить владельца счётчиков/режима: задача устройства принимает движение и команды, либо счётчики снимаются атомарно. Объединение обработчиков в мосте само по себе не устраняет гонку с PS/2-задачей.

### 3. Управление соединением и индикацией — вместе с пунктами 3, 18, 19

- `main.cpp:135–237`, `472–487`: заменить сочетания `pairingRequested`, `pairingAborted`, `bleNowScanning` явным состоянием контроллера соединений и сообщениями между задачами.
- Хранить реальные подключения по устройствам; режим сопряжения не должен подменять состояние соединений общим `isConnected=false`.
- Отдельная задача индикации получает команды: показать Passkey, показать активность, показать режим. Она одна пишет GPIO LED; приоритет отображения кода задаётся явно.
- Callback немедленно возвращается после передачи команды. Отмена и сканирование сигнализируются событиями, без циклов ожидания на общих bool.

### 4. Общие операции PS/2 — вместе с пунктами 5, 7, 15–17

- `esp32-ps2dev.cpp:520–748`, `1014–1214`, `1632–1660`: выделить транспорт, клавиатуру и мышь в отдельные реализации.
- В транспорте сосредоточить таймауты, результат передачи, прогресс пакета, обработку host request и историю для RESEND. При ожидании готовности хоста нельзя удерживать ресурс, необходимый задаче приёма его команды.
- Убрать повторяющиеся циклы `while(write(...)) delay(1)` через небольшие функции с явным результатом. ACK и очередной пакет должны иметь определённый порядок; RESEND клавиатуры и мыши требуют разных правил.
- Обработчики команд можно оставить switch: понятные переходы состояния полезнее универсальной таблицы указателей на обработчики.

### 5. Небольшие локальные упрощения

- `main.cpp:417–470`: таблица `{mask, Button}` и один цикл для изменений кнопок мыши, по примеру уже существующего `kModifierActions`.
- `bt_keyboard.cpp:884–1064`: общий код получения bonded devices, сравнения адресов и освобождения scan results. Обычное сканирование уже использует `is_bonded_device()`, BLE daemon повторяет сравнение вложенными циклами и не проверяет malloc.
- Использовать небольшие RAII-обёртки для владения scan results и semaphore lock, чтобы ранний return не требовал ручного free/unlock. Ошибки создания ресурсов всё равно проверять явно.
- `esp32-ps2dev.cpp:1267–1614`: преобразование ASCII в `{Key, shift}` через constexpr-таблицу вместо большого switch; в текущем приложении этот API не вызывается, поэтому приоритет низкий.
- Проверить необходимость унаследованных `wait_for_ascii_char()`, `get_ascii_char()`, `quick_reconnect()` и неиспользуемого `esp_hidh_dev_report_t`: вызывающего кода в проекте не найдено. Удаление публичных методов требует решения о сохранении библиотечного API.
- Унифицировать имена (`mouse_x_lenght` → `mouse_x_length`, `KeyInfo_CCONTROL` → понятное имя), убрать закомментированные старые реализации и нерелевантные комментарии. Это отдельная небольшая правка после функциональных изменений.

## Выполненный рефакторинг — 2026-10-02

- `main.cpp` теперь содержит инициализацию и короткий цикл обработки; прежний `BTKeyboard` заменён адаптером `BluetoothHost`. API внутренних классов изменён; неиспользуемое преобразование HID в ASCII и `quick_reconnect()` удалены.
- HID-парсер и декодер отделены от ESP-IDF. Контекст разбора локальный, смещения input/output/feature не смешиваются, учитываются global Push/Pop, Report ID, локальные Usage ranges, padding и signed/unsigned поля. Ограничения декодера перечислены в README.
- Состояние ввода хранится по `(device, map_index, report_id)`. Отключение удаляет только состояние этого устройства; удержания остальных сохраняются. Три старые очереди заменены очередью общих снимков. Снимки содержат суммарное относительное движение для восстановления после перегрузки.
- Мост формирует отпускания/нажатия, ставит модификаторы перед обычными make-кодами, хранит явную клавишу автоповтора и сроки по монотонному времени. Отказ PS/2-очереди не продвигает состояние успешно переданных клавиш, поэтому переход будет повторён.
- Сканирование выполняется одной задачей. Запросы сопряжения/отмены передаются сообщениями; отмена применяется после окончания текущего блокирующего вызова сканирования ESP-IDF. BLE/Classic discovery, список bonded devices и освобождение результатов используют общий код.
- Одна задача пишет status LED и показывает все шесть цифр Passkey. Bluetooth callback лишь передаёт код. Команды LED клавиатуры тоже отложены в отдельную задачу; раннее значение сохраняется до готовности Bluetooth.
- PS/2 разделён на транспорт, клавиатуру и мышь. После повторного ревью один worker на порт принимает команды и отправляет ответы/обычные пакеты. При запрете передачи сохраняется позиция ответа/пакета, ожидания готовности под mutex нет. Параметры команд принимает тот же worker при следующих host requests. Проверка CLOCK позволяет прервать кадр и повторить байт. RESET/смена режима отменяет старые пакеты; мост заново передаёт удержания. RESEND хранит последний успешно отправленный байт клавиатуры/полный пакет мыши, включая BAT; ответ FE не заменяет историю.
- Состояния PS/2-устройств защищены отдельными recursive mutexes. Мышь получает движение и кнопки атомарно; счётчики сохраняются при отказе очереди. Фоновая отправка разрешена только в stream mode. Кодирование 2:1 и границ пакета вынесено в чистую функцию; READ_DATA не применяет stream scaling.
- Defaults используют явную `partitions.csv`, без включения обязательного шифрования. Сохранены `0xB000` для таблицы, `0x20000` для приложения и `0x197000` для `nvs_keys`. Локальные `sdkconfig`, `sdkconfig.old` и `.cache/` не редактировались вручную.

## Повторное ревью рефакторинга — 2026-10-02

Предыдущая оценка готовности была слишком оптимистичной: проходившие тесты чистых модулей и сборка не проверяли работу Bluetooth discovery и самого PS/2-драйвера. Повторное ревью выявило и исправило следующие ошибки.

- **[P1, регрессия] BLE discovery фактически отключён.** При переносе потерялся `#define SCAN 1`, но остался `#if SCAN`. В результате ни один BLE scan result не регистрировался. Условный блок удалён; неопределённые макросы в собственных условиях `bluetooth_host.cpp` теперь вызывают ошибку компиляции. Проверено отдельным отрицательным compile-probe; в объектном коде проверен вызов регистрации из BLE callback.
- **[P1, регрессия] Частичная backpressure нарушала порядок клавиш.** Если make модификатора или break старой клавиши не помещался в очередь, последующий make всё равно мог попасть туда после освобождения одного слота. Теперь обработка снимка останавливается на первом отказе; тест воспроизводит отказ одной операции при успешной следующей.
- **[P1, незавершённое исправление] Ответы PS/2 могли ждать бесконечно под bus/state mutex.** Новый host request делал ожидание IDLE невозможным, поскольку обработчик сам удерживал необходимые ресурсы. Убраны циклы ожидания; ответы имеют сохранённую позицию и приоритет над stream. RESET может отменить прерванный ответ. Параметры F0/F3/ED/E8 принимаются отдельными запросами, включая задержку 100 мс в тесте.
- **[P1, регрессия] RESET мог вклиниться между чтением revision и постановкой make/break.** Один keyboard update моста теперь выполняется под mutex состояния; проверка версии и все операции очереди согласованы с обработкой команды. Проверено восстановление удержаний после RESET на настоящем драйвере в модели.
- **[P1/P2, регрессии] HID: составные карты, Usage/range и unsigned32.** Report Size >32 в Feature/Output ошибочно отвергал всю карту клавиатуры. Usage ranges теряли позицию относительно отдельных Usage и поддерживали только одну пару. Unsigned Logical Maximum 0xFFFFFFFF превращался в -1. Исправлено; тестируются широкие служебные поля, смещения vendor input, несколько диапазонов, Array/Variable, signed32/unsigned32 и отказ при превышении 32 Consumer usages без изменения состояния.
- **[P2, регрессия] Короткие клики исчезали между тиками мыши.** Добавлена очередь переходов кнопок; press/release внутри одного интервала формируют два пакета. При переполнении сохраняется конечное состояние и выводится предупреждение.
- **[P2] Разные HID usages с одинаковым PS/2-кодом отпускали чужое удержание.** Keyboard/Consumer aliases объединяются перед вычислением переходов. Проверены Mute в двух usage pages и backslash aliases; Consumer-only удержание не запускает typematic. Отдельно исправлен старый неверный код ISO-клавиши HID 0x64: Set 2 = 0x61, Set 3 = 0x13.
- **[P2] Typematic: регрессия при отпускании и старая неверная таблица.** После отпускания последней повторяемой клавиши больше не возобновляется повтор ранее удерживаемой. Период вычисляется из битов PS/2 rate; default = 92 мс вместо 83, крайний медленный режим = 500 мс вместо 476.
- **[P2, регрессия] LED reconnect мог восстановить устаревшее значение.** OPEN теперь только уведомляет LED worker, который читает актуальный desired state; callback не перезаписывает его старым снимком.
- **[P2] Остальные исправления протокола и discovery.** RESEND запоминает полный успешно переданный пакет; проверяется входящий стоп-бит, ошибочный кадр получает FE; GET_ID мыши сохраняет negotiated mode после обычной смены sample rate и сбрасывается после RESET. Убрано отрицание INT64_MIN и исправлены ожидания около rollover micros. Исправлены границы GAP-полей, чтение bonded list и передача Class of Device вместо адреса указателя. Pairing пробует другие кандидаты, если предпочтительный уже подключён и SDK отклоняет его open.
